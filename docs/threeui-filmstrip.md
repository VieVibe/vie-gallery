# ThreeUI 胶片影展集成

2026-11-03 打磨版。采用“选效果、移植源码、复用现有引擎”的路线，首个效果为胶片影展。

## 使用

- 创作者：配置面板 → 风格 → 胶片影展。默认原片、深灰背景、手动浏览，无粒子和漂浮。
- 访客：底部“胶片”入口，只切换编排，保留当前相册的背景、照片处理和其他设定。
- 桌面和手机均为连续横向胶片展带；支持拖动、方向键、前后按钮和点击查看大图。
- 继续使用“横向胶卷”这个已有编排 ID，已有使用该编排的相册（包括琥珀时刻）也会获得新的连续展带布局；原有照片处理与背景不变。默认推荐风格不变。

## 移植边界

来源为 [ThreeUI Community Character Filmstrip](https://github.com/MengTo/threeui/blob/main/src/shaders/character-carousel/sources/character-filmstrip.html)，核对日期 2026-11-02。

从上游移植的阶段进度与连续浏览思路出发，当前由 FilmRibbon 将照片排入同一圆柱曲面，按原始宽高比分配画格宽度，加入具有真实镂空的胶片边缘。照片与带体共用曲率，拖动时由现有阶段进度平滑驱动。手机使用横向满幅取景，屏幕边缘可能截取部分画面，可点击查看完整照片。

复用 SpatialStagePlugin、TexturePool、PhotoScene、动画时钟、减少动态效果和生命周期。没有增加 React、iframe、渲染器或独立动画循环。几何只在尺寸变化时重新弯曲；切换风格、进入照片编排和卸载时恢复照片原始顶点。

新增 `film-exhibition` 预设并纳入共享配置、管理端卡片和访客快捷入口。服务端已接受 `filmstrip` 编排及字符串预设名称，不需要配置结构或数据库迁移。

## 验证与限制

- 共享契约和 Viewer 单元测试：172 项通过，覆盖小相册、大相册、循环、原比例、对象复用和减少动态效果。
- Viewer 浏览器检查（4 项通过）：胶片浏览、整册循环、打开大图、翻页切回、低画质、手机横向拖动及 1440 / 768 / 390 三种尺寸。
- 首版管理端浏览器检查（2 项通过，本轮未重跑）：卡片、预览图和内嵌 Viewer 读取新配方。
- 使用接口模拟数据及仓库内照片验证；未部署或操作真实用户相册。

视觉检查使用 design-taste-frontend 的浏览器检查器并人工查看三种尺寸截图。检查器仍报告三个不适用于本次产品局部改动的条目：将实际相册页码判作装饰编号、将 WebGL 内多张照片计作单张画布、要求静止的手动相册添加多处自动动效。因此不声称检查器全部通过。保留实际页码和手动浏览行为。

没有进行真实手机 GPU / 耗电基准测试，不能据此宣称性能提升。集成的收益是新的视觉编排，同时继续服从原有资源预算。

## 2026-11-03 视觉复核与回退

本轮为局部效果改造，沿用产品字体，未抽签新的整站方向。桌面为弯曲连续胶片，手机为横向满幅取景；绿色大面板改为中性色轻量控件，标题与作品信息分开布局。人工查看了 1440 / 768 / 390 三种尺寸的真实浏览器截图。主观视觉复核为桌面 7.5/10、手机 7/10；仍有胶片边框较强、窄屏需要点击查看完整构图的取舍，最终保留与否由用户决定。

没有新增外部媒体。演示图片仍为仓库 covers 素材，本地示例相册不代表用户真实相册。

打磨前的文件备份位于仓库内 .cache/threeui-before-polish-2026-11-03/，manifest.json 记录文件清单；本轮新建 FilmRibbon.ts 和 filmRibbon.test.ts。回退时仅恢复这些文件及移除本轮新文件，不影响私密空间等其他未提交工作。新增预览图也已备份。
